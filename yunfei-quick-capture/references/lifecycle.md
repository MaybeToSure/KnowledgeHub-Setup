# 随手记生命周期

## 存储契约

每条记录单独保存，便于独立汇总、分类和归档：

```text
00-Inbox/Human/Quick-Captures/YYYY/MM/<capture-key>.md
10-Sources/Attachments/Quick-Captures/YYYY/MM/<capture-key>/<原文件>
```

记录必须包含稳定 ID、时间、输入方式、原始内容、附件相对链接、附件哈希和处理状态。附件保存在 KnowledgeHub 内，不能依赖聊天临时路径。

随手记 Markdown 和附件必须位于 Obsidian 已打开的 KnowledgeHub 内。AI聊天只是输入通道，Obsidian是人工浏览、补充、修订和审核入口；二者操作同一份文件。

## 共同编辑边界

- `原始记录`保存最初文字或可靠转写，不得静默改写。
- `人工补充`供人工在 Obsidian 中自由补充背景、更正和后续想法。
- `AI整理`只有在人工明确要求后才写入，不得覆盖原始记录或人工补充。
- `处理记录`保存汇总、提炼、分类、归档或转交结果及其链接。
- 人工需要更正原始内容时，优先在人工补充中注明更正；人工仍拥有最终决定权。

## 四级记录

1. 原始记录：保存当时的文字、可靠转写和原始附件。
2. 整理后的记录：补全语境并标记不确定性，始终引用原始记录。
3. 汇总记录：综合多条整理记录，识别主题、重复、矛盾和待决问题。
4. 处理记录：保存人工决定、目标知识/任务/项目、状态和结果链接。

处理记录是进入知识或行动系统的唯一转换门；汇总本身不等于处理决定。

## 明确指令与动作

### 仅汇总

读取指定范围内的记录，在 `30-Notes/Quick-Capture-Summaries` 生成带来源链接的摘要。不得移动原记录；只有用户要求记录处理状态时才修改原记录状态。

### 提炼或分类

逐条区分人工原话、AI概括、事实、推断和待验证问题。新条目引用原始随手记 ID；不得删除或改写原始记录。无法确定分类时留在收集箱。

### 归档

只有已有可追溯汇总、知识条目或人工明确判定“不再处理”的记录可以归档。移动到 `90-Archive/Quick-Captures`，修复链接并保留 Git 恢复证据。

### 同步

先运行知识库健康检查，再审查差异、提交和推送。同步不自动触发汇总、分类或归档。

## 语音和附件

- 语音原文件是来源证据，转写是派生文本；两者都保留并关联。
- 图片可在记录中内嵌预览，同时保留原文件链接。
- PDF可链接或内嵌；Office文件保存原件并交给系统默认应用打开。
- 同名附件不得覆盖；出现冲突时添加稳定后缀。
- 附件复制成功并校验哈希后，才可声称记录完整。

## 输出约定

记录模式只报告保存路径、附件数量和未处理状态。后处理模式报告处理范围、输入数量、生成条目、保留的未决记录、Git状态和失败项。
